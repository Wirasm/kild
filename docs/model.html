§00

The reframe

Today kild's primitive is the Room — and the Room is an opinionated, human-centric, hierarchical group chat baked into the engine. That violates kild's own rule (“ship mechanism, never intelligence”). The reframe makes the primitive the agent, and pushes every opinion up into PRP.

The tell was in the bug history: “who is this addressed to?” has bitten three separate places. That is not carelessness — it is the wrong primitive screaming. A shared broadcast log forces the engine to guess recipients. Directed message-passing removes the question entirely: the sender names the recipient, full stop.

The whole redesign is one substitution, applied everywhere:

  • Room → kild. A kild is a git worktree — the isolated workstream. Membership is “who is in this tree,” not a social construct with its own lifecycle.
  • Participant tiers → one agent. No operator / lead / worker ranks. An agent is an agent; roles are personas PRP hands out, invisible to the router.
  • @human → honryo. The human stops being a participant and becomes an attached agent holding the seat. Authority is a role flesh or a trained proxy can carry.
  • Broadcast chat → directed messages. An agent reaches another only by an explicit send into its inbox. No leads, no implicit replies, no ping-pong.
The one line

Delete the org chart from the engine. Ship spawn + send + isolation + observability + a seat. Let the personas be the team.

§01

Primitives

Six things. Three nouns, three verbs. Everything the engine ships reduces to these; everything else is intelligence.

kild noun
= worktree = workstream

An isolated git worktree and the agents working in it. The unit of parallel work. The root checkout is kild-0; children fork from a base branch. “Room” survives only as the rendered view of a kild.

agent noun
= harness + model + persona

The sole inhabitant type. One mechanism axis: owned (kild runs the process) or attached (an external harness kild addresses but never spawns). Role is intelligence — the engine can't see it.

honryo role
= agent + human authority

An attached agent wearing human-authority intelligence. The human's CLI (Claude Code). Registered so it is addressable — workers send home to it — but its process is the human's, not kild's.

spawn() verb
into: kild  |  fork: base

Any agent creates one or many. into a kild = a collaborator sharing the tree. fork a base = a child kild with a new tree. One verb, one axis — collapses open_room + invite_agent.

send() verb
to: [handle] → inbox

A directed message to named recipients' inboxes, delivered as a turn. The only way an agent's words reach another. No broadcast, no default-to-lead. Collapses post_message + post_room.

seat capability
spawn · stop · kill · guardrails

Hard authority: the unforgeable powers, plus engine guardrails (refuse a push to main, cap spend, hard-halt). Held by the real human. Grantable to a honryo as a client; never delegable at the root.

observe and land round out the verb set — observe is the read side (event stream + git/cost state), land merges a child kild toward its base. Both are pure mechanism; see §05.

§02

Data model

Three types. What's kept is mechanism; the annotations mark what was intelligence and leaves, and what dies outright.

engine/src/kild/kild-types.tswas room-types.ts · Room
// The unit: a kild = an isolated workstream = a git worktree.
interface Kild {
  id: string
  name: string
  cwd: string            // project root the tree derives from
  worktree?: string      // kild/<name>; absent = the root checkout (kild-0)
  base?: string          // parent branch this tree forked from — the tree edge
  parent?: string        // parent kild id — the recursion edge; absent = root
  agents: Agent[]        // inhabitants (owned + attached)
  log: Message[]         // message record — a "room" is just this, projected

  state: RoomLifecycleState   // opening|running|halted|closed — DIES (intelligence)
  decisions: RoomDecision[]   // needs-decision ledger      — MOVES to PRP
  // no "lead" — participants[0] was never a mechanism fact
}
Agentwas RoomParticipant
// The sole inhabitant. ONE mechanism axis (ownership). Role is intelligence.
interface Agent {
  handle: string              // @name — addressable
  ownership: 'owned' | 'attached'  // MECHANISM: does kild run the process?
  persona?: string            // from PRP; kild never interprets it
  model?: string
  spawnedBy?: string          // spawner handle (or the seat) — recursion edge
  inbox: Message[]           // directed messages awaiting a turn

  // owned only — kild owns the subprocess:
  sessionId?: string
  piSessionId?: string        // durable terminal-resume handle

  idle / posted           // report-and-idle failsafe — MOVES to PRP
}
Messagewas RoomMessage
interface Message {
  id: string
  kildId: string
  from: string              // sender handle
  to: string[]              // explicit recipients — the sender always names them
  text: string
  ts: number

  implicit?  // turn-final narration auto-post — DIES (no broadcast to compensate for)
  system?    // engine notice — DIES; observers derive joins/leaves from the event stream
}
What this removes

No HUMAN constant. No lifecycle state machine. No lead. No implicit replies, no to-defaulting, no decision ledger in the engine. Authority is not a field — it lives in PRP and in the seat, never in the row.

The worktree tree — recursion bottoms out at the repo root

Every agent lives in some kild, including the coordinator: the main checkout is kild-0, and spawning either shares a tree or forks a child. Work lands by merging a child's branch toward its parent's base.

§04

Boundaries

The layers connect through narrow, deliberate seams. A violation of any of these is a bug, not a style choice.

BoundaryThe ruleEnforced by
pi ↔ engineOnly the engine knows pi exists. pi shapes are translated into kild domain types in one place; nothing above sees them.engine only
kild ↔ PRPkild ships mechanism, never intelligence. No personas, no process prompts — only the single generic mechanism prompt. PRP arrives via config paths.config paths
role ↔ enginehonryo vs worker is intelligence. The router must never special-case a role the way it once special-cased participants[0].no engine flag
soft ↔ hard authoritySoft authority (who leads, when to report, gate this) is trained deference in PRP. Hard authority (spawn/stop/kill/guardrails) is the seat, in mechanism.seat = client
addressingRecipients are a structured list the sender provides. Never parsed from prose. There is exactly one answer to “addressed to whom?” — the to field.send(to)
Hold this line hardest

Do not delete HUMAN and add HONRYO. That just renames the privileged-participant mistake. The engine knows agents, kilds, edges, messages, and who holds the seat — nothing about what a honryo is. “Defer to this agent” is a fact PRP asserts and personas honour by training.

§05

How they talk

Five operations. Everything the honryo or a worker does is one of these; the transport differs only by ownership.

OpWhat happensTransport detail
spawnCreate an owned agent into a kild (share tree) or fork a child kild (new worktree from base). Any agent may call it; recursion is uniform.engine creates the worktree, spawns the pi worker subprocess
sendDeliver a directed message to each named recipient's inbox as a turn. The sole path between agents.owned: push a prompt to stdin · attached: queue in the inbox, pulled
observeSubscribe to the event stream (text, tool calls, stats) tagged by kild+agent; list kilds with git & cost state.WS broadcast · REST snapshot
stopSeat power: halt an agent or a whole kild; sessions end, the record stays read-only. Worktrees persist.SIGTERM the subprocess; keep the tree
landMerge a child kild's branch toward its base. Mechanism provides the merge + collision report; the decision to land is a PRP gate.git merge/rebase; prune the merged tree
The inbox unifies the two transports

Every agent has one inbox. For an owned agent the engine drains it by writing to the subprocess's stdin (push). For an attached honryo, kild can't push — the CLI pulls at its own turn boundary (the Claude Code Stop-hook drains it). Same data structure, two drain modes. This is the one place the owned/attached axis is load-bearing.

§06

API design

One transport-neutral control plane on localhost:4517. The honryo drives the same REST/WS any UI client drives — there is no privileged operator channel. Mapped against what exists today.

POST /api/kilds/:id/stopSeat: stop agents, keep read-only. Worktree survives.closeRoom / room_close

WS — the event stream /ws

  • subscribe → catch-up snapshot of live kilds, then live { kild, agent, event } UiEvents (text / tool_start / stats / *_end).
  • kild list updates pushed on every spawn / stop / cost change — the observability half.
  • The WS command verbs (room_open, room_post, spawn, prompt, stop) collapse into the REST surface above; WS becomes read-mostly. One command shape, many readers.

§09

Open decisions & build notes

Seven calls to make before the demolition. Each has a leaning; none is settled.

Naming: kild is the product and the unit.
“Open a kild” reads fine, but the collision needs a deliberate ruling so docs don't wobble. Lean: accept it; the unit is “a kild,” the system is “kild.”
What guardrails does the seat enforce?
The only place mechanism enforces safety. Lean: refuse pushes to protected branches, a per-kild spend cap, and a hard-halt — a small fixed set, not a policy engine.
Who may trigger land, and against what gate?
Merge is mechanism; the decision is PRP. Lean: any agent can request a land; the engine runs the merge + collision report; the honryo/PRP gate authorises it.
Unify the inbox across owned & attached?
One inbox, two drain modes (push to stdin vs pull by hook). Lean: yes — it's the one clean home for the owned/attached axis.
Do system notices survive?
Joins/leaves/stops as log rows, or derived from the event stream? Lean: drop them from the log; observers reconstruct from events. Keeps Message pure.
Is the per-kild log stored or projected?
If messages are directed to inboxes, the log is “all messages where kildId == x.” Lean: keep a per-kild index for cheap observability; treat it as a projection, not a source of truth.
How deep does recursion go, and how do sibling collisions surface?
Grandchildren fork from a child's branch; worktree-status.collidesWith already computes sibling overlap. Lean: no depth cap; surface collisions in observe and block land on unresolved overlap.

The engine ships isolation, supervision, messaging, observability, and a control seat — one inhabitant type on two mechanism axes. PRP ships all intelligence, including the honryo and the trained deference that gives it weight. The agent CLI is the honryo — attached, seat-holding, human-steered.
